# v219 星系照片层级与直径修复

## 源码证实的问题

- 照片层基础几何宽1、taper .16后宽.84，但使用体积网格的 `sz*.5`。因此实际照片宽仅目录直径的.42。现在 `sz/.84`补偿，源提取执行makeGalVolumeGeo验证宽度吻合目录直径；不靠提高亮度遮掩尺寸错误。
- 照片和完整程序体积同时绘制。添加默认1的 `uLayerOpacity`，同时缩放预乘radiance和alpha，保持混合一致性；普通已加载照片星系的程序体积默认.22，未加载照片保留1。M51专属体积已经ready时保持独立路径，不按普通照片星系降权。
- 7px硬切换改为5–12px连续resolvedK；照片opacity与程序体积层权重同步淡入，locator尺寸按1-resolvedK退出。仍是艺术LOD，不是观测级分辨率重建。

## 回归与边界

main-redesign所有类型默认uLayerOpacity=1；预乘输出同时权重radiance和alpha断言；实际makeGalVolumeGeo构造执行验证；5–12px源提取连续性；cosmic-depth/main-redesign/cinematic-inline/check-built-content/streaming通过。三正式入口重建完成。

仍无截图构图验收。GPUreadPixels证明运行/层权重生效，不证明艺术审美完成。照片为二维观测影像，程序体积为艺术补充，未变成真实三维重建。
