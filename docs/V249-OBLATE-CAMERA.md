# v249 — 行星扁率，以及一个被藏了很久的相机滚转 bug

## 1. 真实行星都是扁的

八颗行星原来全是正球。实际极半径/赤道半径比：

| 天体 | 赤道半径 (km) | 极/赤道 | 扁掉 |
|---|---|---|---|
| 水星 | 2439.7 | 0.999 | 0.1% |
| 金星 | 6051.8 | 1.000 | ~0 |
| 火星 | 3389.5 | 0.9949 | 0.5% |
| 木星 | 69911 | **0.9355** | 6.5% |
| 土星 | 58232 | **0.9020** | 9.8% |
| 天王星 | 25362 | 0.9773 | 2.3% |
| 海王星 | 24622 | 0.9830 | 1.7% |

做法是把扁率**烘进几何**：`SphereGeometry` 顶点 `y *= polar` 后 `computeVertexNormals()`，
网格缩放保持各向同性。这样着色器里的 `mat3(modelMatrix)*normal`、经纬采样、
环平面、拖拽旋转全都不用改——非均匀缩放会把法线矩阵搞乱，烘进几何避开了这个问题。

**环上的行星影子**也要改：影子边界的形状是扁的。把坐标沿自转轴（= 环面法线）
除以扁率，椭球求交就退化成球求交，射线方向同样缩放：

```glsl
vec3 ocS = (oc - uRingN * ocAx) + uRingN * (ocAx / uPolar);
vec3 LS  = (L  - uRingN * lAx)  + uRingN * (lAx  / uPolar);
```

## 2. 相机 up 把一个 90° 的滚转藏了很久

修扁率时发现木星的云带是**竖着**的。查下去根因不在贴图：

`placeCamera()` 里 `camera.up.copy(_up)`，而 `_up` 来自 `basisAt(cam.dir)` —— 也就是
**「从星球中心指向相机」的径向方向**。贴地时这是对的（径向就是天顶），
但看行星时它把屏幕上方定义成了径向，等于整幅画面绕视轴滚了约 90°：
木星的云带竖着排、土星的自转轴横着躺。

这个 bug 从「能飞到行星旁边看」那天就在了，只是早期行星是程序化表面、
没有方向性强的特征，没人（包括我）看出来。

修法：

```js
if (cam.focus === EARTH) camera.up.copy(efToWorld(_up, _t4));   // 贴地保持径向
else if (Math.abs(_off.y) > 0.985) camera.up.copy(_up);        // 接近天顶才回退，防 lookAt 退化
else camera.up.set(0, 1, 0);                                   // 其余天体：北极朝上
```

修完：木星云带横向、土星环面是正常椭圆、自转轴大致竖直。地球贴地视角不受影响
（走的是第一个分支），地球夜景仍然是黑的——那是太阳在地平线下，不是回归。

## 3. 顺带留下的调试入口

`?uv=1` 会把行星材质替换成 `vec3(vUv.x, vUv.y, 0)` 的 UV 可视化——
这次就是靠它排除了「贴图转置」这个假设，确认了问题在相机基向量。

## 验证

- `tools/test-v249-oblate-camera.cjs`：七颗行星的扁率数值、几何生成、环影椭球求交、相机 up 三分支。
- 实际浏览器（HTTP）：木星 `_p249-a`（云带横向 + 明显扁率）、土星 `_p249b-sat`
  （环面椭圆、轴竖直）、月球与地球贴地正常；修前对照 `v249-before-roll.png`。
- 回归：v246–v240 契约、atlas / cosmic / gaia 打包回归通过；三个入口已重建。

## 仍未做的

- **密度波**：算过可以不做——土星最近机位下环系约 59 km/px，而密度波波长 10–100 km
  是 0.2–1.7 像素，加了只会出摩尔纹；要有意义得先让相机能贴近环面（现在会被星球挡住）。
- **E 环**：τ~1e-5 的厚环面，顺光下不可见，需要专门的体积壳。
