## 3. 四个硬核亮点（问题 → 解法 → 证据）

简历只放 2~3 个，面试再展开。这四个是含金量最高的。

### 亮点 A：14 个数量级的深度精度（最值钱）

**问题**：float32 在 10¹² 尺度下有效精度只剩米级，贴地会抖动、Z-fighting、模型撕裂。
这是所有「星球级」引擎的第一道坎。

**解法**：
- **浮动原点**：相机永远在原点附近，世界坐标相对相机重建，精度不随距离衰减
- **分层尺度**：地表（14 m~km）/ 行星（10⁶~10⁹）/ 宇宙（10¹²+）三套独立坐标系，切换时做连续插值
- **四叉树 LOD + T-junction 缝合**：相邻 LOD 级别接缝处补顶点，避免裂缝
- **地形按像素足迹淡出**：AO、沙滩、细节噪声在远处逐级淡出，避免摩尔纹

**证据**：14 m 贴地 → 3×10¹² m 连续无抖动；推镜 2.8 s；`PROGRESS.md` 有 40+ 轮针对这个问题的迭代记录。

**为什么值钱**：这是图形学里「大世界」的经典难题，能讲清楚说明你真做过。

### 亮点 B：手写大气散射 + 分层体积云（物理渲染深度）

**问题**：天空、云、地表必须是同一个光照模型，否则一眼假；而体积云在掠射角会严重走样。

**解法**：
- **Bruneton 式大气**：透射率 LUT + 单次散射 LUT，天空/地形/云共用
- **多次散射 LUT**：32×64 迭代求 Ψ(r,μs)，让暮光（太阳 −10°）真实成形
- **分层体积云**：低层积云 2.3~5.3 km + 高层卷云 8.2~11.5 km，各自 march、视差、漂移
- **自阴影**：沿太阳方向 0~4 步 light march，云缝亮、云厚暗
- **双瓣相函数**：前向 + 背散，8 km 俯视是真正的云海
- **走样治理**：步长上限、步长感知的频率淡出、云层地形深度测试（治「云刷到山坡上」）

**证据**：8 km 云海、暮光 −10° 成形、贴地斜视无白色椒盐噪点；每个特性都有 `?xxx=0` A/B 开关。

**为什么值钱**：大气散射 + 体积云是实时渲染的「硬骨头」，能自己推导 LUT 维度、能解释走样根因，比调参选手高一档。

### 亮点 C：Schwarzschild 黑洞逐像素光线追踪

**问题**：黑洞不是贴图，是光线在弯曲时空里的传播。

**解法**：
- **测地线积分**：每像素反向追踪光线，`a = -1.5 h² r / r⁵`，**曲率限步的 midpoint RK2**，400 步硬上限
- **解析阴影**：用守恒量 impact parameter `b=|r×v|` 与临界值 `3√3/2` 比较，smoothstep 抗锯齿——替代「二值捕获」造成的锯齿
- **吸积盘**：差速旋转、多普勒 beaming、引力红移、黑体色阶、细丝湍流
- **HDR + Bloom**：HalfFloat RT → 阈值 → 两级可分离高斯 → ACES 合成

**证据**：1.0 ms / 帧（160 步，1667×527）；Bloom 增量 <0.02 ms；前后对比图 `shot150-blackhole-before-after.png`。

**为什么值钱**：把 GR 的测地线方程落到 GPU 上，且知道「哪里是近似」（明确标注非 Kerr、非实拍）——这种分寸感在面试里很加分。

### 亮点 D：真实数据管道 + 可验证的工程严谨

**问题**：天文可视化最容易变成「编数据」。这个项目的做法是接真实数据并做数值校验。

**解法 / 证据**：
- **Gaia DR3**：经 Heidelberg ARI TAP 查询，G≤10、视差 S/N≥10、RUWE<1.4 筛选出 **390,534 条**，`source_id` 用 uint64 字符串精确保留
- **Cassini UVIS**：导入 1 km 光深剖面 **65,985 个有效样本**，区段 τ（C 0.106 / B 3.848 / 卡西尼缝 0.110 / A 0.668）与公开量级一致——用这个来证明「单位/列选择/径向映射都对」
- **115 个自动化脚本**：契约测试（源码必须包含某结构）、数值 oracle（CPU 复算光线轨迹）、像素回归、打包一致性
- **文档诚实性**：每轮明确写「证明了什么 / 没证明什么」，不把采样点通过说成「整体画面验收」

**为什么值钱**：大多数个人项目只有「能跑」，这个有「可验证」。数据许可（CC BY-NC 3.0 IGO）都标注了。

## 5. 面试追问与答法

按被问概率排序。**每个都要能讲到「为什么这么选」，而不是「我做了什么」。**

| 追问 | 答题骨架 |
|---|---|
| **浮动原点具体怎么实现？** | 相机位置作为原点，所有顶点在提交前减去相机位置；关键是「哪些量必须保持世界坐标」（光照方向、天体位置）vs「哪些可以相对」（顶点、法线）。切换尺度时做位置插值而不是跳变。 |
| **大气 LUT 为什么是 2D？维度怎么定？** | Bruneton 模型：透射率 LUT 只依赖 (r, μ)，单次散射依赖 (r, μ, μs, ν) 但可降到 2D 查表 + 解析相位函数；多次散射用 32×64 迭代求各向同性平均辐亮度 Ψ(r, μs)。分辨率是精度/显存折中，误差看的是「暮光能否成形」。 |
| **体积云怎么防走样？** | 三层：① 步长上限（8 km → 掠射时压到 1.2 km）；② 步长感知的频率淡出（步长大于噪声尺度就降频，但**只降频不切低频场**，否则会变成百叶窗）；③ 云层参与地形深度测试（治「云刷到山坡上」）。踩过的坑写在 TECH-NOTES。 |
| **黑洞为什么用 RK2 不用 RK4？** | 每像素 400 步，RK4 是 4 倍函数求值；测地线方程是中心力场，曲率限步的 midpoint RK2 在光子球附近已经稳定（实测半步 vs 四分步方向误差收敛）。用 RK4 的收益抵不过 4 倍成本。 |
| **115 个测试怎么组织？** | 四类：源码契约（shader 必须包含某结构，防误删）、CPU 数值 oracle（用 JS 复算光线轨迹/τ 积分，和 GPU 结果对量级）、像素回归（同会话 A/B，看 meanAbs 与基线噪声）、打包一致性（三入口 md5、离线不请求外部资源）。 |
| **性能瓶颈在哪，怎么定位的？** | 分阶段：shader 编译（首屏）→ 地形构建（切块卡顿）→ 逐帧渲染（draw call / overdraw）。工具：帧时间条形图、GPU timer query、`?q=` 档位对照、动态分辨率。关键结论：**瓶颈会随视角变**（贴地是 overdraw，太空是星点填充率）。 |
| **400 MB 单文件是不是设计失误？** | 是刻意的取舍：目标「双击就能离线跑」，所以把 3D 纹理/星表/照片全部 base64 内联。代价是首屏加载，因此另做了 HTTP 分离版（26 MB）+ PWA 缓存 + 渐进加载。**如果重做，会默认分离、单文件作为导出选项。** |
