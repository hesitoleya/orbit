# v244 — 「做不到」的那些，怎么解决

先说结论：六条里**一条已经做掉**（金星 2k），**两条有明确工程路径**（LDEM 高分辨率、Cassini τ），
**一条在物理上不需要解**（环厚度），**两条只能等新数据或换模型**（粒子动力学、海王星分辨率）。

## 已经做掉：金星 2k 云顶 → 双层（云顶 / 雷达地表）

原来写的是「金星可见光云顶公开上限 2k，提不上去」。这句没错，但它只说了**一层**。
金星地表有 Magellan 的 8k 全球雷达图——那是真实观测，只是波长不同。

- 新增 `data/planet-maps/venus-surface.jpg`（源 8192×4096 → 压到 4096×2048，2.1 MB）；
- `PLANET_ALT` 表 + `setPlanetLayer()`：切换时同时把大气权重从 0.95 降到 0.30
  （雷达穿透云层，看到的是地面，不该再压一层厚霾）；云顶纹理缓存住，切回来是瞬间的；
- 入口三个：界面按钮（只在停到有第二层的天体时出现）、`?venus=surface|cloud`、
  `__SE.setPlanetLayer('venus','surface')`；
- 来源与边界写进 manifest：**雷达反照率的色相是按高程/粗糙度做的示意着色，不是可见光颜色**。

这条路可以复制到别的天体（火星的夜侧热图、木卫的伽利略拼接图……），是「2k 天花板」的通用解法：
**换一个波段，而不是给同一个波段注水。**

## 有明确路径：月球 LDEM 从 16 ppd 到 32 ppd

现状 16 ppd（1.9 km/px）。上一级是 `LDEM_64`（46080×23040 uint16 ≈ **2.1 GB**）。

**可行性已验证**：`pds-geosciences.wustl.edu` 的 `ldem_64.img` 支持 Range 请求
（实测 `HTTP 206`），可以流式读、边读边降采样，不需要落 2.1 GB 到磁盘。

两条路线，按代价排序：

### A. 一次性做 32 ppd 包（推荐先做这个）

1. 流式读 `ldem_64.img`，2×2 平均降到 **32 ppd**（11520×5760，uint16，132 MB）；
2. gzip 后约 40–60 MB，存成 `moon-ldem32.bin.gz`；
3. 前端用 `DecompressionStream('gzip')` 解压（Chrome/Safari 都支持），不依赖服务器；
4. **懒加载**：只有相机到月球的距离 < 3×10⁶ m 时才去取，并显示「加载月面高清高程」提示；
5. 纹理从 R16F 16 ppd 换成 32 ppd（显存 16.6 MB → 66 MB，桌面可接受）。

预期收益：法线细节从 1.9 km/px 到 0.95 km/px，和 4k 反照率（0.85 km/px）对齐——
近景坑缘不再靠纹理"画"出来。

### B. 真正的全分辨率（64 ppd，0.38 km/px）：切片流式

1. 构建期把 LDEM_64 切成 2048² 的 tile（每片 8 MB，uint16），
   按经纬度命名 `tiles/z3/x/y.bin`，共约 23×12 = 276 片；
2. 运行时按相机星下点取 3×3 片（≈72 MB）拼成一张区域纹理，与 16 ppd 全局图
   在着色器里按距离混合；
3. 走到哪、铺到哪，显存占用恒定（≈72 MB），全月面都是 0.38 km/px。

代价：要写 tile 管理器（缓存、LRU、混合权重、卸载），是本项目里第一块真正意义的
「虚拟纹理」。收益是「放大到地平线仍有细节」——和地球地形那一套是同一个思路。

## 有明确路径：Cassini 逐圈 τ 剖面

真值在 PDS `COUVIS_8001`（438 MB tar.gz，200+ 次 UVIS 恒星掩星，1 km / 10 km 两套剖面）。

**卡在哪（已实测）**：`pds-rings.seti.org` 对本环境的出口 IP 返回
`Access Denied: error code bacf8917…`（Anubis 反爬的 IP 级拒绝）。换 headless Chrome
走完整 JS 挑战同样被拒——所以不是「不会解 PoW」，是这台机器/代理的 IP 被挡了。

**解法**：在住宅网络（或任何未被拦的网络）用浏览器手动下载，然后离线处理
（**具体网址与一条命令的接入方式见 [V246](V246-TAU-IMPORT.md)**：
`https://pds-rings.seti.org/viewmaster/volumes/COUVIS_8xxx/COUVIS_8001/` 浏览，
或整包 `COUVIS_8001.tar.gz`（438 MB）；接入用 `node tools/import-couvis-tau.cjs <剖面.TAB>`）：

1. 下载 `COUVIS_8001.tar.gz`，解到 `DATA/` 目录；
2. 取一条**入环（ingress）**、恒星仰角较高的 1 km 剖面（例如 β Cen / α Leo）；
   文件是固定宽度的 `.TAB`，列里有 `RADIUS`（km）与 `TAU_NORMAL`；
3. 按半径插值到现有 2048 点 LUT，替换 `satRingLut` 的 `tau` 通道（反照率仍按区给）；
4. 记录 profile 名、恒星、rev、仰角——τ 随仰角变化（自引力尾迹），必须写清用的是哪一条。

工作量：拿到文件后 1–2 小时。这一步做了，`τ 剖面` 就从「公开区值」变成「实测」。

## 物理上不需要解：环厚度

主环局部厚度 10–20 m = 3×10⁻⁷ 行星半径。本项目最靠近土星的机位（约 1.3×10⁸ m）
下一个像素覆盖 300 km 以上——厚度在任何允许的缩放里都是**亚像素**。
把它建模成薄盘不是偷懒，是分辨率意义上正确的选择。要做「有厚度」的环，
前提是先把相机放到离环 10 km 以内，那是另一套近景环粒子场景，不属于当前产品。

## 只能换模型 / 等数据

**粒子动力学（自引力尾迹、密度波）**
两条路：
1. **线性密度波解析解**（便宜，一两天）：在 A/B 环已知的 Lindblad 共振半径处
   （如 Janus 2:1、Mimas 5:1…）叠加 `m=2` 螺旋图案，振幅随半径按理论衰减。
   这是真实的物理结构（Cassini 图上那些细密波纹就是它），只是不含非线性演化。
2. **预计算 N 体/SPH**（贵）：离线算一次，把结果烘焙成 64 帧密度序列，
   运行时按时间滚动采样。能做，但那是把「渲染」变成「回放」，且体积大。

**G / E 环**
E 环是 3–8 R 的**厚环面**，τ ~ 10⁻⁵，只在背光前向散射时可见。
正确模型是体积散射壳，不是薄盘。做法：加一个加法混合的环面体积着色器
（解析密度 ∝ exp(−((r−r₀)/w)²)·exp(−(z/h)²)，配双瓣 HG），代价约 100 行 GLSL。
但它在顺光下几乎不可见——加了之后大部分时间看不出来，属于「加分项，不是硬伤」。

**海王星 2k**
没有解法。1990 年至今没有航天器再访，唯一全球图是旅行者 2 号那一套。
要更高分辨率只能等新任务（或接受「合成增强」——那就是造假，不做）。
