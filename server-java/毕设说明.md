# SPACE·1:1 行星引擎 —— Java 毕业设计改造说明

> 适用场景：把已有的 SPACE·1:1（1:1 尺度行星/宇宙实时引擎）作为**Java 方向毕业设计**提交。
> 本说明面向院系评审，解释“为什么是 Java 项目、Java 部分做了什么、论文怎么写”。

---

## 1. 问题背景与改造动机

SPACE·1:1 原本是一个**纯前端 + Node.js** 的 WebGL 行星引擎：浏览器用 Three.js 做实时渲染，
后端仅用 Node 提供静态文件托管与少量数据接口（`server/server.mjs`）。
它**不含任何 Java 代码**，无法直接作为 Java 毕设。

改造目标：**在保留成熟前端渲染能力的前提下，用 Java（Spring Boot）重写后端服务层**，
使项目拥有合格、可答辩的 Java 技术栈，同时新增一个“真正用 Java 写”的数据处理模块，
为论文提供可陈述的**核心算法 / 模块**。

---

## 2. 需求分析

| 编号 | 需求 | 来源 |
|---|---|---|
| R1 | 托管前端静态资源（HTML/JS/图片/数据），行为与原版一致 | 原 server.mjs |
| R2 | 提供 `/api/peaks` 供地形加载真实高峰高程数据 | 前端依赖 |
| R3 | 提供 `/api/health`、`/api/stats` 用于服务自检与资源审计 | 原 server.mjs |
| R4 | HTTP 缓存（ETag + 304）+ gzip，保证改代码即生效、重复请求零流量 | 原 server.mjs |
| R5 | **新增 Java 数据处理模块**：解析真实天文星表并统计聚合 | 毕设核心增量 |
| R6 | 工程可编译、可运行、可打包，技术栈为 Java | 院系要求 |

## 3. 架构设计

```
                ┌──────────────────────────────┐
   浏览器 ─────►│  Spring Boot 内嵌 Tomcat     │
 (前端 public/)  │  ┌──────────┬─────────────┐  │
                │  │ 静态资源  │  REST /api/** │  │
                │  │(public/) │             │  │
                │  └──────────┴──────┬──────┘  │
                └───────────────────┼──────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
        EtagFilter            ApiController          FaviconController
       (缓存/304/统计)      /health /peaks          (/favicon.ico)
                            /stats /cosmos
                                   │
                    ┌──────────────┼───────────────┐
                    ▼              ▼               ▼
              StatsService   CatalogService     Metrics
            (目录遍历清单)  (★星表解析聚合)    (运行指标)
                    │              │
                    └──── 读 public/data/*.json ──┘
```

- **表示层**：Spring MVC `@RestController` 暴露 REST 接口。
- **服务层**：`StatsService`（NIO 递归遍历）、`CatalogService`（Jackson 解析 + 流式聚合）。
- **过滤层**：`EtagFilter` 实现 HTTP 缓存语义与流量统计。
- **数据层**：只读前端既有 JSON 数据文件（`peaks.json`、`mwgc.json`、`galmap.json`），
  后端不持有数据库，符合“薄服务层”定位。

## 4. 核心模块（论文可重点写）

### 4.1 静态资源缓存过滤器 `EtagFilter`
复刻 Node 版 `W/"<sizeHex>-<mtimeHex>"` 的 ETag 生成规则；命中 `If-None-Match` 时
返回 `304 Not Modified`，不重传文件体；含**目录穿越防护**（`startsWith(root)` 校验）。
可作为“HTTP 缓存机制 / Web 安全”章节案例。

### 4.2 ★ 天文星表数据处理模块 `CatalogService`（毕设核心增量）
纯 Java 读取 Harris 星表导出的 `mwgc.json`（144 个真实球状星团）与 `galmap.json`（星系目录），
完成：
- 星团**视星等**的极值与均值计算；
- 星团**日心距离**（kpc）均值计算；
- 星系按 **type 字段分组计数**（流式 `Collectors.groupingBy`）。

这部分是“原项目没有、由 Java 后端补齐”的真实算法工作，建议作为论文
“数据处理 / 流式计算”章节的主例，接口为 `GET /api/cosmos`。

## 5. 关键技术与创新点（答辩可用）
1. **Java 21 + Spring Boot 3**：内嵌 Tomcat、自动装配、可执行 jar，工程标准化。
2. **Record 作为 DTO**：用 Java 21 `record` 表达响应体，代码即契约，Jackson 直接序列化。
3. **NIO 流式文件遍历**（`Files.walk`）+ **Stream 聚合**（`Collectors.groupingBy`）。
4. **HTTP 缓存语义复刻**：ETag + 304 与压缩，保证与原前端无缝对接。
5. **零数据库、薄服务层**：后端只做“托管 + 数据加工”，与重前端解耦，易于部署。

## 6. 测试方案
- **编译/打包测试**：`mvn clean package -DskipTests` 成功产出 jar。
- **功能冒烟测试**（建议写进论文“系统测试”节）：
  - `GET /` 返回 `text/html` 且含 `<canvas>`/前端入口；
  - `GET /api/health` 返回 `{ok:true, ...}` 且 `uptimeSec` 递增；
  - `GET /api/peaks` 返回 JSON 且 `peaks` 数组非空；
  - `GET /api/stats` 返回 `total>0` 且 `files` 按体积降序；
  - `GET /api/cosmos` 返回 `globularCount=144`、各星等/距离统计与星系分类计数；
  - 二次请求同一静态资源时响应码为 `304`（验证 ETag）。
- **对照实验**：同一浏览器分别走 Node 后端与 Java 后端，前端渲染结果一致（截图对比）。
